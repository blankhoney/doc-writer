# 编排
主 session 开工前读本文件。
每个阶段的产出都写成文件，上层只记路径和一行摘要，因为读代码和读资料的原文会挤占写作和判断的上下文。

## 三层分工
| 层 | 数量 | 做什么 | 不做什么 |
|---|---|---|---|
| 主 session | 1 | 定义文档集，指定术语表和共享契约的权威文档，派 lead，派核查，汇总，交付 | 读代码，写正文 |
| lead | 每篇文档 1 个 | 本文的 orchestrator：派探索 subagent，用总结写 brief 和术语表，派新上下文的写作 subagent，合稿 | 读代码 |
| subagent | 按需 | 只做一件事，结果写进文件 | 再决定文档结构 |

规则：
1. lead 缺事实时，派补研 subagent，不自己翻代码。
2. 长文可按章节派写作 subagent，由 lead 合稿，统一术语并去重。
3. 每个 subagent 回交一行摘要和文件路径，不回贴正文。
4. 派出的 agent 没有全部返回，不进入下一阶段，也不交付。
5. 产出文件缺失或 subagent 被限流，就重派或改为串行，不跳过这一阶段。
6. 子 agent 提示只写任务和产出。写作规则由它自己读对应的参考文件，提示里不重复。

子 agent 用便宜模型即可，推理强度调高。写作和核查可用较强模型。
环境允许时，也可以用命令行调其他模型（如 `pi -p`）。环境不能派子 agent 时，按同样的阶段自己做，每阶段结束只保留文件；核查按三张表依次自查，并在交付说明里写明没有独立核查。

## 工作目录
放在临时目录或用户指定的位置，交付后按用户意愿处理。
- `definition.md`：文档做什么、读者、要回答的问题、范围、篇数、前提。
- `notes/<主题>.md`：研究笔记，每条带 `文件:行号` 或 URL。
- `edges.md`：研究中发现的边界、竞争、风险、疑问，每条附证据。
- `resolutions.md`：对 `edges.md` 每条的处理和依据。
- `questions.md`：待问用户的问题，每问附推荐答案；交付时一次提问。
- `brief.md`、`glossary.md`、梳理文件：大纲、术语表、产品梳理或架构与数据模型。
- `evidence/<核查名>.md`：核查证据表。

## 阶段
### 1. 定义（主 session）
写 `definition.md`，五到十行：
- 文档做什么：读者读完要做出什么决定或动作。
- 读者：按使用者、运维、开发者、评审者分层，写明主要读者。
- 要回答的问题：三到八个，后面每个阶段都以它为准。
- 范围：覆盖什么、不覆盖什么、依据哪个版本的代码。
- 片段类型：各对应哪份写作指南。
- 用户视角：需要的端到端示例和界面呈现。
- 前提：部署规模、并发假设、已接受的取舍、用户已定的决定。后面判断一个边界会不会发生、要不要重新讨论，都以它为准。

一个请求默认写一篇。只有用户要求，或两类读者在一篇里完成不了任务时才拆分。
拆成多篇时，每条契约、状态定义和术语只归一篇文档定义，其他文档链接过去。
多篇按 PRD、设计、API 与 Runbook 的顺序写，下游以上游为准。
前提不清楚的，按代码和常规用法定一个，记进 `questions.md`。

### 2. 研究（lead 派探索 subagent）
并发派 4–6 个，每个一个主题：代码、数据与配置、已有文档、架构分析。
技术类常见主题有数据模型、状态与转换、主要流程与失败路径、错误与重试、已有文档和测试声称的行为。definition 的问题要求时，再加并发与一致性。
产品类先研究用户、场景、痛点和现状，再看现有能力。
探索 subagent 把看到的边界、竞争、风险和疑问追加到 `edges.md`，每条附证据，不写进主题笔记的结论，因为未经取舍的发现不应被写作 agent 当作必须覆盖的事实。
```text
任务：回答 <问题列表>。范围：<目录或 URL>。只读。
产出：<工作目录>/notes/<主题>.md，每条一行事实，附 文件:行号，推断单独标出；边界、竞争、风险、疑问追加到 <工作目录>/edges.md。回交一行摘要。
```

### 3. 解决（lead 派一个分诊 subagent）
分诊 subagent 先读 `definition.md` 和 `references/review.md`，再按顺序处理 `edges.md` 的每一条：
1. 代码、配置或已有文档能回答的：查清，写成事实或决定（「选 X，因为 Y」），进 brief。
2. 与前提矛盾、真实使用中不会触发的：删除。
3. 施工期能决定的：删除。
4. 必须由人决定、并且会改变范围或结构的：先查已有文档、ADR、设计说明、代码注释、提交信息、能访问的 issue 和 PR 讨论，因为这件事可能早已权衡过；查到的按已定的取舍写成一句决定。查不到的记进 `questions.md`，每问附推荐答案，文档里不写。

提问不阻塞写作，两条线互不等待。文档写完后，主 session 把 `questions.md` 的问题一次问用户：
- 用户确认要写的，派 lead 补进文档，补完只对改动处重跑核查。
- 用户答不需要处理或已考虑过的，直接丢弃，不再跟进。
`resolutions.md` 每条写：条目、处理（事实／决定／删除／待问）、依据。

### 4. 梳理（lead）
读全部笔记和 `resolutions.md`，写 `brief.md`（每节一句要回答的问题和依据的笔记）、`glossary.md` 和梳理文件。
术语表列为：术语、定义、代码标识、不要混用的近义词。
- 同一个词只指一个对象。指两种以上时各起限定名，如「schema 版本」「期望版本」。
- 状态名在正文、表格、图里写法一致，首次出现写中文名和代码值。
- 业务动作各写清触发者、前置状态和结果状态，同一动作不换近义词。
- 术语表放进文档的「术语」节。多篇文档只放一处。

### 5. 写作（写作 subagent）
lead 派新上下文的写作 subagent，长文按章节派多个，由 lead 合稿。写作 subagent 只读 `brief.md`、术语表、梳理文件和以下参考，不读 `edges.md`：对应的 `references/writing/` 指南、`references/formatting.md`、`references/review.md`、`references/constraints-writing.md`、`references/unslop.md`。
写作 subagent 只写结论，不把没有结论的讨论写进文档。缺事实时派补研 subagent。

### 6. 核查（主 session 并行派 3 个 agent，lead 统一修改）
核查 agent 不继承写作上下文，各自可再派 subagent。它们只写证据表 `evidence/<核查名>.md`，不改文档，因为并行改同一份文档会互相覆盖。

| 核查 | 做什么 | 证据表列 |
|---|---|---|
| 事实与一致 | 抽出每个可核查的断言：名称、字段、默认值、数值、状态、调用关系、行为。按章节分给 subagent 逐条找依据：代码、用户给的日志与材料、已定决策。多篇文档或仓库已有文档之间，对每个术语、契约、默认值全文搜索，列出所有出处 | 断言、文档位置、依据（`文件:行号` 或材料名）、符合／不符／无依据、建议 |
| 需求与范围 | 用户原话和 `definition.md` 的每个问题都要对应到文档章节，标出遗漏、多写和偏离。再换成评审者、接手人的身份只读文档，标出每句「可能……」「需要注意……」「是否应该……」，以及没有结论的风险、竞争、边界。每条按「解决」阶段的顺序回溯：能查清的改写成事实或决定，查不清的删除，并记进 `questions.md`。文档里出现未解决的讨论，视为上游漏解决 | 条目、对应章节、判断、建议（补写／改写／删除） |
| 文风与排版 | 按下面五步 | 位置、问题、依据、建议 |

文风与排版核查按顺序做：
1. 用一句话复述全文主旨和章节结构。复述不出来就判结构不合格，先报结构问题。
2. 运行 doc-lint，逐条判断候选，包括 G1 表和排版候选。
3. 按 `references/unslop.md` 逐条扫，按 `references/formatting.md` 逐条对照。步骤和规则类句子应是祈使句。
4. 对每个关键结论问四件事：假设是什么，证据在哪，有无替代方案，后果是什么。
5. 逐章过六项：清晰、准确、精确、相关、深度、逻辑。

三个 agent 全部返回后，lead 读三张证据表，一次改完：
1. 不符的按依据改正；无依据的删除，或标为待确认。
2. 跨文档冲突只改用户授权修改的文档，同一项只留一个权威出处，其余链接过去；未授权的文档只在交付说明里列出。
3. 两张表的建议冲突时，以事实为先，再顾排版。
4. 改完重跑 doc-lint，把每条的处理结果补进证据表。

主 session 读完三张证据表和 lead 的处理结果才交付，抽查两三处改动。

```text
任务：核查 <文档路径列表>，核查类型：<名称>。依据：<definition.md、代码路径、术语表、用户材料>。
先读 <参考文件>。证据表写入 <工作目录>/evidence/<名称>.md，列为 <表头>。不改文档。回交一行摘要。
```

交付说明三五行：写了什么、依据哪些代码、删减了什么、还有哪些没核对。之后附上 `questions.md` 的问题，每问一行，附推荐答案。
