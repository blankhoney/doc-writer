# 编写规则

动笔前与 `references/rules.md` 一起读。本文件也是候选扫描器的词源，G1 表格的格式不要改。

#### G1. 禁用模式清单

**解决的逃逸**：模型容易合理化自己的措辞。命中后按上下文裁决；不影响原意的措辞优先删除，不为保留补解释。

**禁用句式**：

| 类别 | 模式 | 处理 |
|------|------|------|
| 万能开场 | "随着……不断发展/深入推进" | 删除，直接从主题开始 |
| 万能开场 | "在……背景下/大趋势下" | 删除 |
| 跳过论证 | "众所周知/不言而喻" | 删除，补上被跳过的论证 |
| 冗余句式 | "对 X 进行了 Y" | 改为 "Y 了 X" |
| 冗余句式 | "存在……的问题/现象" | 直接陈述问题 |
| 冗余句式 | "具有……的特点/能力" | 直接说特点 |
| 冗余句式 | "做出了……的决策/贡献" | 直接说决定/做了什么 |
| 无效总结 | "综上所述/总体来看/由此可见" | 删除 |
| 逃避决策 | "需要结合实际情况综合判断" | 删除，改为说明缺什么信息 |
| 逃避决策 | "后续持续优化/不断完善" | 删除，改为列出具体待办 |
| 逃避决策 | "具体情况具体分析/后续根据实际情况调整" | 删除，改为列出待决定项和决策条件 |
| 万能结尾 | "开启新篇章/迈向新阶段/具有重要意义" | 删除 |
| 无效连接 | "此外/同时/值得注意的是/在此基础上" | 无必要时删除；保留“同时升级”等实际条件 |
| 伪深度标记 | "本质上/核心在于/底层逻辑" | 删除引导词；如果后续有实际新信息则保留信息部分 |
| 机械拆分 | "首先……其次……最后……"（当内容可合并为一句时） | 合并为一句直接陈述 |
| 转折否定铺垫 | "……但……不等于……" | 直接说明可用范围、限制、条件或待验证项；真实引文与契约原文保留 |
| 与假想敌辩论 | "有人可能会认为/有人会问" | 删除，直接陈述结论与条件 |
| 借权威 | "业界普遍认为/专家指出/众多实践表明" | 给出具体出处，没有出处就删除 |
| 客服腔 | "希望对您有帮助/如有疑问/欢迎随时" | 删除 |
| 谈论上一稿 | "相比上一版/在上一版中" | 删除；变更记录放进对应文档 |

**禁用修饰词**（除非后接具体度量）：显著、深入、全面、充分、有力、极致、高效、强大、无缝。

**禁用抽象大词**（除非当场用一句话定义其在本文中的具体含义）：

- 通用大词：赋能、协同、闭环、抓手、范式、沉淀、生态
- 架构大词：解耦、复用、演进（仅在未说明具体变化时禁用）
- 程度化大词：统一、全局、一体化、平台化、标准化（仅在未论证统一/标准化必要性时禁用）

#### G3. 排除性检验

**解决的逃逸**：判断规则只要求"给判断"，模型可以给出形式正确但内容空洞的判断。

**验证方法**：

> 如果你的结论替换成相反的结论，论据部分是否需要重写？如果不需要——论据没有真正支持结论。

**示例**：

失败案例：
```
"建议采用微服务架构，因为它更灵活、可扩展。"
→ 替换成"建议采用单体架构"，论据几乎不需要改。
→ 论据是通用废话，检验未通过。
```

通过案例：
```
"建议采用单体架构。当前团队 4 人，服务间调用延迟预算 < 10ms，
未来 12 个月用户量预计不超过 5 万。微服务的运维开销（服务发现、
链路追踪、独立部署流水线）在这个规模下是净负担。"
→ 替换成"建议采用微服务"，整段论据必须全部重写。
→ 论据确实在支持结论，检验通过。
```

#### G4. 中文表达与排版

技术文档用中性陈述句说明事实，操作步骤用祈使句（可省略主语）。不追求"像人写的"：不加个性、口语、感叹或刻意的节奏变化；作者有依据的判断照常保留。

**句子**
- 优先用主动语态，少用"被"字句。
- 避免双重否定；同一个意思优先用肯定句。
- 重复表达同一含义的限定词只留一个；"可能"（确定程度）和"在一定程度上"（影响幅度）含义不同，不算重复，能写出具体条件时改写成条件。
- 名词前不叠多个"的"字定语，拆成两句。

**结构**
- 同级只有一个子标题时取消该层；下级标题不重复上级标题的名称。用户指定的骨架和模板固定格式除外。

**排版**
- 中文与半角英文之间加一个半角空格；中文与数字之间加不加空格全文统一（扫描器的 spacing 格式项可定位候选）。
- 粗体只标结论、警告和界面元素，不用于装饰性强调。
- 破折号只用于插入说明或解释，不用来串联本应分开的句子。
- 标题不加表情符号或修饰性前缀。

来源：句法与排版规则改编自阮一峰《中文技术文档的写作规范》（公共领域）；与假想敌辩论、借权威、客服腔等 G1 模式借鉴 Humanizer-zh（op7418，MIT）中适用于技术文档的删除型规则思想，未复制其文本，不引入其"作者声音"部分。
