# 研究笔记
笔记分两层，因为一行结论装不下调用链、存储位置和失败分支，写作者只读结论会写错。先读索引，写到哪个机制再打开哪篇笔记。

- `notes/index.md`：每个主题一行，写成 `主题 | 问题编号 | 两三句结论 | notes/<主题>.md`。轻量档没有问题编号时留空。
- `notes/<主题>.md`：一个机制或一组相关事实一篇。按下表写，没有内容的节省略。

| 节 | 写什么 |
|---|---|
| 结论 | 三到五句：机制做什么、关键参数、失败时怎样 |
| 调用链 | 编号步骤，从入口到结果，每步写函数和 `文件:起始行-结束行` |
| 数据与存储 | 读写哪些键、字段、表或流，何时写、何时删、过期时间 |
| 参数、默认值与公式 | 名称、默认值、取值来源、计算公式 |
| 分支与失败 | 条件、行为、结果状态 |
| 代码摘录 | 写入存储、默认值与公式、分支条件、抛错和捕获处的代码，原样摘录并标 `文件:起始行-结束行` |
| 例子 | 用一组具体输入沿调用链走一遍，写出每步的值和最终状态 |
| 疑问 | 推断、冲突和没查清的地方，各写查过哪里 |

- 写现有实现时，沿调用链读完源码再写结论，因为只读入口会漏掉分支和真正的存储位置。目标设计和历史按已定设计、记录取依据。
- 每篇笔记首行写依据的版本：提交号、文档日期或材料名，因为代码变了旧摘录会让旧结论通过核查。版本与定义不符时重研。
- 笔记要让后续的写作和核查不必再搜索代码：结论有摘录或行号可查，最容易写错的存储位置、默认值、公式和分支给原样摘录。
- 每条事实附依据：`文件:行号`、URL、材料名或用户原话。推断标「推断」。
- 同一事实只记在一篇笔记里，其他笔记链接过去。用户答复或核实后改写原处，不追加相反的说法。
