# 去 AI 味
改写自 unslop（Lauren Tan，backnotprop/pstack，MIT 许可）。

已列的规则见 `references/constraints-writing.md`、`references/formatting.md` 和 `references/orchestration.md`。

doc-lint 扫 G1 和排版候选，本文件的条目靠人判断。
判断候选时问：这句话告诉读者要做什么、知道什么？答不出就删，答得出就照答案改写。

## 内容
- 把感受改成机制或数字，因为读者需要知道如何使用。
- 删除放进别的项目也成立的句子，因为它没说本项目的事。
- 把空泛结论改成具体计划、日期或事实，没有就删。
- 直接写结论，不先立一个没人提的说法再推翻。

## 用词
- 把抽象隐喻换成实际组件、数字或动作，因为比喻没有明确含义。
- 用「是」或「负责」写关系和职责，因为句子更短、主语更清楚。
- 用常用词替代花哨词，因为读者能更快读懂。
- 用测得的差值或耗时替代撑起弱动词的副词；没有数字就删副词。

## 句子
- 有几个要点就写几个，不为节奏凑成三个。
- 删除两端不在同一尺度上的假范围，直接列出涉及事项。
- 把格言、刻意断句和拟人化代码改成字面描述，因为修辞不说明行为。

## 标点与格式
- 只在列表、示例和定义前用冒号；句中两半改成完整陈述，因为悬念会打断阅读。
- 删除只复述正文首词的列表标签；标签给出对象、后文给出新信息时保留。
- 从列表和表格删装饰性 emoji，状态用文字表示；标题见 `references/constraints-writing.md`。
- 中文正文统一用「」或“”，代码和命令用直引号。
