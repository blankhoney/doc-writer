# 去 AI 味

改写自 unslop（Lauren Tan，backnotprop/pstack，MIT 许可），按中文技术文档重写，条目已删减和合并。

写作 agent 动笔前读，对齐 agent 逐条扫一遍。
`references/constraints-writing.md` 的 G1 表已列的套话、修饰词和抽象大词，这里不再重复；doc-lint 只扫 G1，本文件的条目要靠人判断。
判断每条候选时问一句：这句话告诉读者要做什么、知道什么？答不出就删，答得出就照答案改写。

## 内容

- **说感受，不说机制**。「部署很顺滑」「配置一目了然」只给感受。改成机制或数字，例如哪条命令完成部署、要填几个字段。
- **放进别的项目也成立的句子**。这类句子没说本项目的任何事，删掉。
- **空泛结论**。「未来可期」「为后续打下基础」不给读者新信息。改成具体计划、日期或已知事实，没有就删。
- **过度对冲**。「可能在一定程度上或许会」叠了三层不确定。留一个限定词，能写出条件就写条件。
- **「不只是 X，更是 Y」**。这种句式先立一个没人提的说法再推翻。直接写 Y。

## 用词

- **抽象隐喻名词**。G1 已列赋能、闭环、抓手、范式；底座、飞轮、北极星、护城河、链路（作比喻时）同理。换成实际的组件名、数字或动作。
- **「作为……」「扮演……角色」「承担……职责」代替「是」**。直接写「是」或「负责」，句子更短，主语更清楚。
- **同义词轮换**。同一段里「任务」「作业」「job」轮着用，读者会以为是三个东西。选一个名字，全文重复它，名字以术语表为准。
- **花哨词代替常用词**。「赋予……能力」写成「让……能」，「进行处理」写成「处理」，「借助」写成「用」。常用词更快读懂。
- **用副词撑起弱动词**。「大幅提升」「快速完成」，换成测得的差值或耗时；没有数字就删副词。

## 句子

- **被动句不说动作主体**。G4 要求优先用主动语态；改写时写出谁做了这个动作，例如「调度器校验参数」，因为读者排查问题时要知道该看哪个组件。主体未知或无关时才用被动。
- **凑三**。为了节奏把要点凑成三个。有几个写几个，两个就写两个。
- **假范围**。「从存储到网络」「从开发到运维」两端不在同一尺度上时，这个范围没有意义。直接列出涉及的事项。
- **修辞腔**。格言式短句、为效果而断开的句子、拟人化的代码（「调度器想要」「这个字段记住了」）。改成字面描述。
- **过度压缩**。箭头、自造缩写、无动词短语，例如「参数错 → 退出 2，不写盘」。写成完整句子：「参数格式错误时，程序以退出码 2 退出，不写入任何文件。」表格单元格和图里的短标签不受此限。
- **长句**。读者需要回读才能理解时就拆开，一句只讲一件事，长度标准见 `references/review.md`。

## 标点与格式

- **破折号**。G4 已限定它只用于插入说明。中文技术文档里这种插入通常也能改成逗号或另起一句，优先这样改。
- **冒号**。冒号用在列表、示例和定义之前。句子中间用冒号连接前后两半，多半是在制造悬念，改成完整的陈述句。
- **加粗滥用**。G4 规定粗体只标结论、警告和界面元素。每个专有名词、每段首词都加粗时，读者找不到真正的重点。
- **「标签：复述」式列表**。形如「**性能：**性能提升了……」，标签只是把正文首词重说一遍。改成连贯的句子；标签点出对象、后文给出新信息时可以保留。
- **装饰性 emoji**。从标题、列表和表格里删掉。状态表需要符号时用文字（「通过」「失败」）。
- **弯引号与直引号混用**。全文选一种引号。中文正文用「」或“”，代码和命令里用直引号。
