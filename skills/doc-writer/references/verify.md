# 核对

初稿完成后读本文件。核对分三步：子 agent 对照实现核对事实，主 agent 按清单自检，最后运行候选扫描。

## 1. 事实核对

按 `references/delegation.md` 第 4 节派全新子 agent 核对事实、示例和链接。涉及文档集时做全文对齐（`references/doc-set.md` 第 5 节）。

关键文档（多人评审的设计、对外发布的文档）可再做一次读者测试：派一个全新子 agent 扮演目标读者，只给它文档，问三五个读者真正要回答的问题（"这个状态能不能直接改成完成？""失败的消息去哪了？"），答不上来或答错的地方就是要改的段落。

## 2. 自检清单

| 项 | 检查 |
|---|---|
| 定义 | 读者、用途、范围与第 1 步的文档定义一致；没漏用户要求的内容 |
| 结论 | 开头给结论或用途；每节首句概括本节 |
| 标题 | 用模板标准名或名词短语，没有结论句、状态句；步骤标题按模板用祈使句，用户指定的骨架照用 |
| 覆盖 | 性质文件（`product-docs.md` 或 `tech-docs.md`）中与本项目相关的重点都写到了，没有的不硬写 |
| 语言 | 产品文档用产品语言，不混入函数签名和 SQL；技术文档术语准确、讲取舍 |
| 事实 | 标识、数字、行号、示例输出与实现一致 |
| 一物一名 | 同一对象同一个名字；多义词加了限定；术语表中一个代码标识只出现在一行 |
| 简洁 | 没有铺垫、重复、凑数章节；未知只在未决问题出现，写作过程（跑没跑、渲染没渲染）在交付说明里 |
| 呈现 | 图、表、代码块按 `references/formatting.md` 选用；图回答明确的问题 |
| 禁用句式 | 按 `references/constraints-writing.md` 的 G1 检查 |

## 3. 候选扫描

正文已保存时运行 `SKILL.md` 中的扫描命令。扫描器只定位套话、修饰词和中文格式候选，命中不等于违规，零命中也不等于通过；逐条判断后修改或保留。项目有自己的格式规范时，可在 `--` 前加 `--skip-format punctuation`、`spacing` 或 `parentheses`。退出码 `2` 表示执行故障，在交付说明里写明。
