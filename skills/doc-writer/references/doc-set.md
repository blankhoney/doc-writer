# 文档集维护

任务涉及两篇及以上文档，或修改的文档与其他文档共用术语、契约或流程时，完整读取本文件。文档集指描述同一项目、互相引用的一组文档。

## 1. 篇数

一个请求默认产出一篇文档。只有用户要求，或两类读者的任务确实无法在一篇里完成时才拆分。已有文档能容纳的内容写进已有文档，不另建新文件。

## 2. 权威归属

每条契约、规则、状态定义和术语只在一篇文档里定义，这篇就是它的权威文档；其他文档用一句话说明用途，再链接过去，不复述内容。

| 内容 | 默认权威文档 |
|---|---|
| 接口、字段、参数、错误码、配置项 | Reference 或 API 文档 |
| 状态、状态转换、业务动作 | 描述该流程的 Explanation 或技术设计 |
| 设计决定及理由 | ADR 或技术设计 |
| 术语 | 文档集的术语表 |

阅读单元执行所需的前提条件、鉴权契约、操作步骤和安全警告可以摘录到多处，摘录与权威文档逐字一致，并链接到权威文档。项目已有约定时沿用项目约定。

## 3. 术语表

文档集只维护一张术语表，放在独立的 `glossary.md` 或文档目录页；放进 README 时放在许可证之前。其他文档需要术语表时链接它，不另建。每条一行：

| 术语 | 定义 | 代码标识 | 不要混用 |
|---|---|---|---|
| 期望版本 | 写入请求携带的版本号，与当前版本不一致时拒绝写入 | `expected_version` | 版本、schema 版本 |

- **一词一义**：同一个词在文档集里只指一个对象；反过来，一个代码标识只对应一个术语。"版本""状态""任务"这类词同时指两种以上对象时，每种各起限定名（"schema 版本""期望版本"），不再单独用裸词。
- **状态**：状态名在正文、表格、图和日志示例中写法一致，第一次出现时写中文名和代码值（"已领取（`claimed`）"）；状态转换表只放在权威文档里。
- **业务动作**：登记、领取、接纳这类动词各自写清触发者、前置状态和结果状态，同一个动作不换用近义词。
- **代码标识**：开发者文档中的函数、字段、枚举值照原样写在反引号里，与中文名对应，不意译。面向使用者的文档不写私有实现（如下划线开头的函数）；需要提到的公开名称与术语表一致。

## 4. 读者分层

文档集按读者分层：使用者、运维、开发者、评审者，项目只有其中几类时只写这几类。每篇文档只有一类主要读者，在开头一句交代读者和用途；入口文档按读者分流。

面向使用者的文档从用户目标和用户看到的结果写起，不从内部模块写起：

- **端到端示例**：文档集至少有一个覆盖主要业务流程的完整示例，从用户输入、经过的操作到最终可见的结果，放在 Tutorial 或 How-to 里，其他文档链接它。
- **运行界面**：产品有界面、命令行输出或报表时，用真实截图或真实运行输出展示关键步骤的结果。拿不到真实输出时写"待补截图"，不编造界面。

## 5. 修改后全文对齐

修改文档集中任何一篇，即使只改了一个词，交付前都做一次全文对齐：

1. **列变更**：写出本次改了什么，例如改名（旧名 → 新名）、契约变化（字段、默认值、状态转换、错误码）、删掉的概念。
2. **派低成本子 agent 查找**：agent 支持子 agent 时，用可选的最低成本模型启动一个全新子 agent，交给它变更清单、文档集文件列表和术语表，要求它只查找、不修改，返回 `文件:行号`、原文和问题类型：旧名残留、与权威文档矛盾的契约、权威文档之外的重复定义、裸用的多义词、术语表中对应多个术语的代码标识。不支持子 agent 时，主 agent 按变更清单逐项搜索全部文档。
3. **主 agent 核实并修改**：逐条打开原文确认后再改。子 agent 的结果是线索，不是结论。
4. **更新术语表**：改名或新增概念时同步术语表。

交付说明写明对齐范围和未对齐的文件。
