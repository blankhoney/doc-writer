# 排版与结构
写作 agent 动笔前读，文风核查 agent 逐条对照。
排版决定读者能不能扫读，所以先选呈现方式，再动笔写句子。

## 呈现方式
| 内容 | 用 | 不用 |
|---|---|---|
| 有先后的动作 | 编号步骤，每步以动词开头 | 段落里写「首先……然后……」 |
| 3 项及以上的并列事项 | 列表 | 一句里用顿号或 (1)(2) 罗列 |
| 多属性对照、枚举、多分支的结果 | 表格，单元格不超过 2 句 | 每项一段重复同一结构 |
| 状态转换、多方交互、分支流程 | 图，图前一句引出，图后写解读 | 用文字复述图里已有的内容 |
| 论证和因果 | 短段 | 把推理拆成互不相连的列表项 |

## 硬线
1. 纯文字段落不超过 200 字、5 句。超过就拆段，或改成列表、步骤。
2. 单个分句不超过 40 字。超过就在连词处拆开。
3. 一句里串联的事项超过 2 个，改成列表。
4. 标题不超过 3 级，不跳级。标题用标准章节名或名词短语，不写成结论句。
5. 列表每组不超过 5 项，超过就分组。字段、状态、错误码表不受此限。

## 字符
- 加粗只用于界面元素和列表项开头的行内标题（「术语。定义」）。强调靠措辞，因为满篇加粗等于没有重点。
- 函数、字段、参数、路径、文件名、命令、环境变量、状态码用行内代码，不加引号。占位符写成 `<名称>`。
- 多行内容放进围栏代码块并标注语言，因为读者要整段复制。
- 中文与英文之间加半角空格；中文与数字之间加不加，全文统一。

## 结构
1. 开头写 3–5 句摘要：现状、问题、本文回答什么、一句话答案。读者只读开头也能知道结论。
2. 每章首句写本章结论，其后才是支撑。只读各章首句应能拿到全文结论。
3. 故障和错误按「现象、原因、处理」三列写，因为排查的人按现象查起。
4. 结果写成可验证的现象，例如返回什么、状态变成什么，不写「确保正常」。
5. 删开场白、复述、客套。真实的不确定保留一句。
6. 压缩只在句内做：删虚词，保留因果、条件、否定和单位。不写成箭头和自造缩写。

## 图文比例
- 篇幅较长的章节至少有一张图、表或列表，整节纯文字会让读者失去落脚点。
- 整节只有图表、没有解释，也不合格。每张图表前后各有一两句话说明它回答什么、读者该注意什么。
