# 图、表与代码块

用图、表或代码块前读本文件。先看信息之间是什么关系，再选呈现方式。

## 1. 选择呈现方式

| 信息关系 | 用 | 不用 |
|---|---|---|
| 有先后的动作 | 编号列表 | 段落里串"首先、然后" |
| 并列的独立要点 | 无序列表 | 硬凑成表 |
| 两个以上维度的对照 | 表格 | 散文逐条比较 |
| 结构、状态、交互、分支 | Mermaid 图 + 一段说明 | 只有文字 |
| 代码、命令、配置、输出 | 代码块 | 正文里的长行内代码 |
| 论证和取舍 | 短段落 | 拆成碎列表 |

## 2. 图

| 读者想知道 | 图类型 |
|---|---|
| 系统由什么组成、谁依赖谁 | `flowchart`，用 `subgraph` 标出进程或存储边界 |
| 对象有哪些状态、怎么转换 | `stateDiagram-v2`，转换边上写触发动作和守卫条件 |
| 多方如何交互、失败时怎样 | `sequenceDiagram`，用 `alt`／`opt` 画失败和超时分支 |
| 请求按什么条件分流 | `flowchart` 判断节点 |
| 数据实体之间的关系 | `erDiagram` |
| 分阶段计划 | `gantt` |

画得好看、读得懂：

- 一张图回答一个问题，图前一句话说明它回答什么。
- 节点控制在十个左右，超过就拆成总览图和细节图。
- 节点名用名词，边上标签写动作或条件（"pop：claim_id + 1"），标签短而具体。
- 图里的名称与正文、代码一致；同一图内方向统一（`TD` 或 `LR`），避免交叉回边。
- 不加装饰性样式和颜色；需要区分时用 `subgraph` 或少量 `classDef`，并在图下说明含义。
- 文字补充图里没有的依据和限制，不逐条复述箭头。
- 纯线性步骤和只有两个组件的关系不画图。
- 能渲染时渲染一次检查可读性；不能渲染时核对语法。

## 3. 表格

- 每列有表头，同一列内容同类（不混数字和描述）。
- 单元格不超过两句；放不下说明内容不适合表格。
- 常用表：比较表（方案 × 维度）、规格表（字段、类型、默认值、说明）、状态表（条件 → 结果）、映射表（概念对应）。

## 4. 代码块

- 标注语言（`python`、`bash`、`json`、`text`）。
- 实际代码核对来源；输出写真实运行结果，没运行的不写输出。
- 按理解需要截取，不截断语法；省略处用注释写明省略了什么。

## 5. 排版

- 标题一般不超过三级；标题层级和粗体的用法见 `references/constraints-writing.md` 的 G4。
- 段落短，一段一件事；长文开头给目录或一句导读，章节之间不重复内容。

## 6. 模板"排版"列的含义

| 排版 | 怎么写 |
|---|---|
| 倒金字塔 | 首句给结论或要点，后面按重要性递减补细节 |
| 问题→方案→代价 | 依次写要解决的问题、选定方案、放弃了什么 |
| 有序步骤 + 验证信号 | 编号步骤，关键步骤后写"应看到……" |
| 定义列表 | 每行"**键**：值"，用于少量属性或配置 |
| 契约表 | 字段、类型、是否必填、默认值、说明等固定列的表格 |
| 时间线 | 按时间排列的条目，每条有日期或阶段 |
| 差异对照 | 前后或两方案逐项对照的表格 |
| 决策日志 | 按时间记录的决定，每条写决定、理由、日期 |
| 索引 + 深链 | 条目列表，每条一个链接和一句用途 |
