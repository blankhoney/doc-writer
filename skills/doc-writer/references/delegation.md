# 委派子 agent

取材和核对前读本文件。主 agent 负责定义文档、判断取舍和成稿；查找、摘录、梳理机制和核对事实交给子 agent 并行做。材料只有几个短文件时可以自己读，其余情况都要委派。

## 1. 分工

| 档位 | 适合的模型 | 做什么 |
|---|---|---|
| 低成本 | 可选的最便宜模型（如 Haiku 级） | 定位和摘录：列出全部状态、字段、错误、配置项、调用点；读日志和大文件取数；按清单搜索旧名 |
| 中档 | 中等模型（如 Sonnet 级） | 分析：推导状态机和守卫条件，梳理主要流程和失败路径，比较备选方案，写示例并运行 |
| 主 agent | 当前模型 | 文档定义、取舍判断、大纲、成稿、确认子 agent 的结论 |

不支持选模型时用默认子 agent；不支持子 agent 时主 agent 按同一份清单自己做，并在交付说明写明。

## 2. 取材清单

按文档定义列出要查明的问题，一个子 agent 负责一个主题。技术文档常见的主题：

- 数据模型：实体、字段、类型、约束、索引、默认值。
- 状态与转换：状态枚举、每个转换的触发函数、守卫条件、非法转换的结果。
- 主要流程：入口函数到结束的调用链，事务和锁的边界。
- 错误：抛出的异常和返回的错误值，各自的触发条件、调用方可见的结果。
- 兼容与迁移：版本号、迁移步骤、旧数据如何处理。
- 已有文档、示例和测试：它们声称的行为，与代码是否一致。

产品文档常见的主题：现有能力与限制、用户反馈或问题记录、相近产品的做法、需求涉及的现有数据。

## 3. 派发要求

给子 agent 的提示写清：

- 要回答的问题和范围（目录、文件）。
- 返回格式：每条事实一行，附 `文件:行号` 或来源链接；推断和事实分开标。
- 返回上限（如不超过 40 行），只要结论，不要贴大段原文。
- 只读，不改文件；外部网页只回传带来源的事实。

互不依赖的主题同时派发。收回后主 agent 抽查关键事实，有矛盾时让子 agent 补查或自己读原文。

## 4. 核对

初稿完成后派一个全新子 agent，只给它文档（路径，或尚未保存时的正文）和源码路径，不给写作过程和预期答案，让它：

- 逐条核对文档中的事实、标识、行号、链接与实现是否一致；
- 运行示例代码，核对输出；迁移、删除、部署等会改变外部状态的命令只做静态核对；
- 列出文档没覆盖、但读者完成任务需要的内容。

主 agent 逐条打开原文确认后再改。子 agent 的结论是线索，不是定论。涉及文档集时，按 `references/doc-set.md` 第 5 节做全文对齐。

## 5. 委托写章节

正文默认由主 agent 写。长文中互不依赖的章节可以委托子 agent 起草：提示里给出 `SKILL.md`、所选模板和相关规则文件的路径，要求先读再写；收回后主 agent 统一改稿，按 `references/verify.md` 核对。
