# 产品介绍、README 开头、发布说明与对比
用运营和产品营销的语言讲清这是什么、适合谁、比现有做法好在哪，并给出证据。
读者是潜在用户和使用者，他们大多只扫读每段首句。

## 标准章节
产品介绍和 README 开头：

| 章节 | 要回答的问题 |
|---|---|
| 一句话定位 | 这是什么，给谁用，解决什么问题？ |
| 核心价值 | 每个关键功能给用户带来什么改善？ |
| 证据 | 有哪些可复现的数字、案例或对比支撑上面的说法？ |
| 与替代方案对比（可选） | 用户现在用什么，换成本产品好在哪、差在哪？ |
| 开始使用 | 怎么安装，最小可运行的示例是什么？ |
| 求助与维护（可选） | 去哪里提问，谁在维护？ |

发布说明每个版本一节，最新的在前，写版本号和日期（YYYY-MM-DD）。
变更按新增、变更、弃用、移除、修复、安全分组，破坏性变更放最前并附升级步骤。

## 语言要点
- 每个功能问一句「所以呢」，写出用户得到的改善。说不出改善的功能不是卖点。
- 目标用户写具体。写成「适合所有团队」，读者就判断不了是否适合自己。
- 用客观、具体的事实，少用形容词。夸大会让读者连真实的部分也不信。
- 数字附条件：硬件、数据规模、版本、对比对象。没有条件的数字无法复现，也无法比较。
- 对比表选项为列、属性为行，不超过 5 个选项。每个属性在各列用同样的口径填写，不偏向自己。
- 产品文档里不用「新」「最新」「即将」，需要时写版本号或日期，否则文档一过期就会误导。
- 链接文字写目的地，不写「点击这里」。
- 发布说明写变更本身和对用户的影响，不搬提交记录。

## 这一类的反模式
- 功能罗列，没有对应的用户收益。
- 只和弱对手比，或换了测试条件再比。
- 发布说明漏掉弃用和破坏性变更。
