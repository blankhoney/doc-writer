# Tutorial（教程）
> 在导师引导下，让学习者通过动手完成一个有意义的目标来获得技能——不是教知识，而是给体验。

> **示例使用范围**：本模板通过变体结构、必需内容、模块与类型验证标准使用，不附样本正文。见[来源说明](../examples/SOURCES.md)。

## 变体选择

```
读者需要学什么？
  ├─ 单一技能，30 分钟内完成       → 最短路径
  ├─ 需要配置环境 / 选择工具        → 带配置
  └─ 多语言 / 多平台 / 多框架       → 多语言分轨
```

需要引导学习时默认走**最短路径**；Quickstart 若只帮助已有基础的读者使用一次主要功能，改选 How-to 任务食谱，不因文件名强选 Tutorial。

## 变体 A: 最短路径

> 一条直线到达可工作的结果，零分支零选择。用于快速入门教学时，首屏给真实主要功能的最小可复制操作与结果确认，必要前提短放操作前；进阶配置、手工验收与扫描细节后置，不因辅助工具依赖阻断主要功能。手动调用与写入授权保留，作者读规则和留检查记录不变成读者练习。

### 必需内容

| 必需内容 | 本节回答 | 排版 |
|--------|------|------|
| **概述** | 你将完成什么（具体产物）？ | 倒金字塔：一句话目标 |
| **前提条件** | 开始前需要什么环境、权限与知识？ | 无序列表：每项写明版本或权限；需要安装的工具附检查命令、预期输出和安装命令。读者环境已满足时省略本节 |
| **步骤** | 从零到可工作结果的每一步 | 有序步骤 + 验证信号；每步一个祈使句子标题 |
| **验证** | 怎么确认你做对了？ | 有序步骤：最终验证命令/截图/预期输出 |

**步骤格式规范**：

每步以一个祈使句作子标题（"安装依赖""创建配置文件"），其下必须包含三要素：
1. **动作**：一个具体命令或操作（`运行 X` / `编辑 Y` / `点击 Z`）
2. **预期结果**：`你应看到 ...`（终端输出 / 页面变化 / 文件生成）
3. **衔接**：下一步为什么需要这个结果（一句话。可省略条件：下一步的输入就是上一步的输出，且两步在同一工具/文件中操作）

禁止：
- 同一步包含两个独立动作（拆成两步）
- 给读者选择（"你可以用 A 或 B"——选一个，写死）
- 插入超过两句的解释（链到 Explanation 文档）

### 按需模块

| 模块名 | 本节回答 | 排版 | 格式规范 | 保留条件 |
|--------|------|------|---------|-----------|
| 故障排查 | 读者在这一步卡住最可能是什么原因？ | 定义列表 | 每条：错误现象（终端输出） + 原因 + 修复命令 | 每条错误有具体修复命令 → 有效；"请检查配置"无具体指引 → 无效 |
| 另见 | 做完之后可以学什么？ | 无序列表 | 2-3 个链接，每个一句话说"你将学到 X" | 每个链接指向真实存在的文档 → 有效；"更多内容请参考官方文档"→ 无效 |
| 概念旁注 | 这步背后的原理是什么？ | 引用块 | `> **为什么？** 一句话解释 + 链接到 Explanation` | 不超过两句 → 有效；变成段落讲解 → 无效（违反 Diátaxis 边界） |

## 变体 B: 带配置

> 需要配置环境或在固定选项中做一次性设定。每个配置项给唯一推荐值，不让读者自己选。

### 必需内容

| 必需内容 | 本节回答 | 排版 |
|--------|------|------|
| **概述** | 同最短路径 | 倒金字塔 |
| **前提条件** | 需要安装/配置什么？推荐什么值？ | 有序步骤 + 验证信号，含环境配置 |
| **步骤** | 同最短路径 | 有序步骤 + 验证信号 |
| **验证** | 同最短路径 | 有序步骤 |

**前提条件中环境配置的特殊规则**：
- 每个配置项给出唯一推荐值，不给替代方案
- 配置放在前提条件，不并入步骤，可跳过（如果读者已配置）
- 配置完成有明确验证信号

### 按需模块

同最短路径模块 + 以下追加：

| 模块名 | 本节回答 | 排版 | 格式规范 | 保留条件 |
|--------|------|------|---------|-----------|
| 替代配置 | 不用推荐配置时怎么调整？ | 定义列表 | 每种替代配置：配置值 + 对后续步骤的影响 | 说明了对后续步骤的具体影响 → 有效；只列可选值 → 无效 |

## 变体 C: 多语言分轨

> 同一个目标，多种语言/平台/框架各走独立路径。每条轨道是一个完整的最短路径变体。

### 必需内容

| 必需内容 | 本节回答 | 排版 |
|--------|------|------|
| **概述** | 同最短路径（与语言无关的目标描述） | 倒金字塔 |
| **前提条件** | 共同前提，以及各轨道所需的运行时/工具（按轨道分条） | 同最短路径 |
| **轨道选择** | 读者用什么语言/框架？ | 索引 + 深链（每个轨道一个链接） |
| **轨道 N** | 该语言的完整步骤 | 有序步骤 + 验证信号 |
| **验证** | 所有轨道共享同一个验证标准 | 有序步骤 |

**分轨规则**：
- 轨道之间不共享步骤（即使步骤相同也独立写出——读者不应在轨道间跳转）
- 轨道选择不解释差异（不是对比分析，是"你用什么就选什么"）
- 最多 4 条轨道，超过则拆为独立教程

### 按需模块

同最短路径模块。

## 类型验证标准

### 结构检查

| 检查项 | 通过标准 | 违反时处理 |
|--------|---------|-----------|
| 每步有验证信号 | 每个步骤都有"你应看到"或等效的预期结果描述 | 补充预期输出 |
| 无读者选择 | 步骤中不出现"你可以选择 A 或 B"或"根据你的偏好" | 选定一个方案，删除替代项 |
| 无概念堆砌 | 连续解释性文字不超过两句；无参数表、无完整 API 列表 | 删除解释，链到 Reference/Explanation |
| 步骤单一动作 | 每步只有一个操作指令 | 拆分为多步 |
| 目标具体 | 概述中的目标是具体产物而非抽象能力；快速入门首屏有主要功能的最小操作与结果确认，不以辅助工具或作者检查代替 | 恢复学习路径；若只需使用一次而非教学，改选 How-to |

### Diátaxis 边界检查

| 检查项 | 违反信号 | 处理 |
|--------|---------|------|
| 不混 Reference | 出现参数表、完整配置列表、API 签名清单 | 移到 Reference 文档，此处只用当前步骤需要的最小参数 |
| 不混 Explanation | 出现"为什么这样设计"的段落、历史背景、对比分析 | 压缩为一句 `> **为什么？**` 旁注 + 链接 |
| 不混 How-to | 出现"如果你想做 X 的话"分支、面向已有经验的读者假设 | 删除分支，保持单一路径 |

### 质量检查

| 检查项 | 通过标准 |
|--------|---------|
| 可完成性 | 一个符合前提条件的读者，按步骤操作能到达验证结果，无需外部查找 |
| 时间合理 | 单个变体的步骤在 30 分钟内可完成（超过则拆分为多部分） |
| 前提明确 | 前提条件有版本号和验证命令 |
| 代码反例 | 易错步骤提供错误写法与正确写法的对比（"故障排查"模块或步骤内 `> **注意**` 旁注），帮助读者识别典型错误 |
| 复杂度渐进 | 代码示例从最简形式开始，每步只增加一个概念；不在第一个示例中展示完整生产配置 |
