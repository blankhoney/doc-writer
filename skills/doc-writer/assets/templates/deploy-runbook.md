# 部署/Runbook
> 让执行者照着做就能完成部署、处理告警或交接值班，不需要理解系统全貌。

> **示例使用范围**：本模板通过变体结构、必需内容、模块与类型验证标准使用，不附样本正文。见[来源说明](../examples/SOURCES.md)。

## 变体选择

```
文档的用途？
  ├─ 部署一个版本到生产环境                      → Deploy Guide（默认）
  ├─ 值班收到告警后的处理流程                    → 告警 Runbook
  ├─ 日常运维操作（备份/扩缩容等），或嵌入手册的单条操作 → 操作手册
  └─ 团队交接或新人接手                         → 交接包
```

## 变体 A: Deploy Guide

部署指南。读者是执行部署的工程师，可能不是代码作者。每一步必须可复制执行、有验证信号。

### 必需内容

| 必需内容 | 本节回答 | 排版 |
|--------|------|------|
| 概述 | 部署什么版本？这次有什么变更？ | 倒金字塔 |
| 前提条件 | 部署前需要什么权限、工具、环境？ | 定义列表 |
| 步骤 | 每一步做什么？怎么确认这一步成功？ | 有序步骤 + 验证信号 |
| 验证 | 部署完成后怎么确认整体成功？ | 有序步骤 |
| 回滚 | 出问题了怎么退回去？ | 有序步骤 + 验证信号 |
| 联系人与升级 | 出问题找谁？多人协作时谁执行、谁审批、谁值守？ | 契约表：角色、负责人、联系渠道、职责 |

### 按需模块

| 模块名 | 本节回答 | 排版 | 格式规范 | 保留条件 |
|--------|------|------|----------|-----------|
| 系统概述 | 部署涉及哪些组件和依赖？（概述的子节） | 倒金字塔 + Mermaid 图 | 一张组件图 + 一段话说明部署影响的范围 | 有组件图且标注了部署影响范围则有效；只有"见架构文档"外链则不需要此模块（直接给链接） |
| 配置变更 | 这次部署需要改哪些配置？ | 定义列表 | 键：变量名、值（示例）、环境、生效方式 | 有具体变量名和示例值则有效；"更新配置"无细节则无效 |
| 数据迁移 | 需要执行数据库迁移吗？ | 有序步骤 | 每步有命令 + 预计耗时 + 验证查询 | 有具体迁移命令和回滚命令则有效；"执行迁移"无命令则无效 |
| 分批发布 | 分几批发布？每批的范围和观察时间？ | 时间线 | 每批：范围、发布时间、观察指标、推进条件 | 有日期和推进条件则有效；"逐步推进"无节点则无效 |

## 变体 B: 告警 Runbook

值班工程师收到告警后的处理手册。读者是值班工程师，可能在非工作时间处理紧急告警——每一步必须机械可执行，不要求理解原理。

### 必需内容

| 必需内容 | 本节回答 | 排版 |
|--------|------|------|
| 概述 | 这个告警意味着什么？ | 倒金字塔 |
| 影响 | 影响范围多大？ | 倒金字塔 |
| 诊断 | 如何判断根因？ | 有序步骤 + 验证信号 |
| 处置 | 怎么修？ | 有序步骤 + 验证信号 |
| 联系人与升级 | 什么情况下需要升级？升级找谁？ | 契约表：升级条件、联系人、联系渠道 |

### 按需模块

| 模块名 | 本节回答 | 排版 | 格式规范 | 保留条件 |
|--------|------|------|----------|-----------|
| 相关监控 | 应该看哪些 dashboard / 指标？ | 定义列表 | 键：Dashboard 名（含链接）、关注指标 | 有具体链接和指标名则有效 |
| 历史案例 | 这个告警以前出现过吗？怎么解决的？ | 时间线 | 每条：日期、根因、解决方式 | 有具体案例则有效；"以前也出过"无细节则无效 |
| 另见 | 还有哪些相关文档？ | 无序列表 | 每条一个链接 + 一句用途 | 链接存在且用途明确则有效 |

## 变体 C: 操作手册

日常运维操作（备份、扩缩容、证书轮换等），也用于嵌入 Runbook 或运维手册的单条操作。读者是运维或值班工程师，需要标准化操作步骤；比 Deploy Guide 精简。

### 必需内容

| 必需内容 | 本节回答 | 排版 |
|--------|------|------|
| 概述 | 这个操作做什么？什么时候需要做？由告警触发时写告警名或症状 | 倒金字塔 |
| 前提条件 | 需要什么权限和工具？ | 定义列表 |
| 步骤 | 每一步做什么？怎么确认这一步成功？ | 有序步骤 + 验证信号 |
| 验证 | 操作完成后怎么确认整体成功？ | 有序步骤 |
| 回滚 | 操作出问题怎么撤回？ | 有序步骤 |
| 联系人与升级 | 做不了、做完没用或出问题时找谁？ | 契约表：条件、联系人、联系渠道（值班不能卡住，必须有升级路径） |

### 按需模块

| 模块名 | 本节回答 | 排版 | 格式规范 | 保留条件 |
|--------|------|------|----------|-----------|
| 执行频率 | 多久执行一次？自动化了吗？ | 定义列表 | 键：频率、自动化状态、cron 表达式 | 有具体频率则有效 |
| 风险 | 操作可能造成什么影响？影响哪些服务和用户？ | 无序列表 | 每条：风险 + 受影响的服务或用户 + 影响方式 + 缓解措施 | 每条风险有缓解措施且列出具体服务名则有效；"可能影响用户"无具体对象则无效 |

## 变体 D: 交接包

团队交接或新人接手时的系统运维全貌。读者是接手者，需要了解系统的运行全貌。

### 必需内容

| 必需内容 | 本节回答 | 排版 |
|--------|------|------|
| 概述 | 这个系统做什么？服务谁？ | 倒金字塔 + Mermaid 架构图 |
| 日常操作索引 | 常见操作的入口在哪？ | 索引 + 深链 |
| 告警与响应 | 有哪些告警？每个告警的 Runbook 在哪？ | 契约表 |
| 联系人与升级 | 出问题找谁？按什么顺序升级？ | 定义列表 |

### 按需模块

| 模块名 | 本节回答 | 排版 | 格式规范 | 保留条件 |
|--------|------|------|----------|-----------|
| SLO 与监控 | 关键指标有哪些？在哪看？ | 契约表 | 列：指标、SLO、Dashboard 链接 | 有具体指标和链接则有效 |
| 已知问题 | 有哪些已知但未修复的问题？ | 无序列表 | 每条：问题、影响、临时方案、计划修复时间 | 有具体问题描述和临时方案则有效 |
| 架构决策 | 接手者需要知道哪些历史决策？ | 索引 + 深链 | 指向 ADR 库 | 有具体 ADR 编号和链接则有效 |

## 类型验证标准

通过核对清单（`references/verify.md`）后，额外检查以下部署/Runbook 专用项：

| # | 检查项 | 判定标准 |
|---|--------|---------|
| D1 | 步骤可执行 | 每个步骤有可直接复制的命令或明确的 UI 操作路径，不是"部署服务" |
| D2 | 验证信号 | 每个关键步骤后有"你应看到"验证，执行者无需猜测是否成功 |
| D3 | 回滚有命令 | 回滚步骤同样有可复制命令，不是"回滚到上一版本" |
| D4 | 配置有示例值 | 涉及的配置项有示例值（可脱敏），不是"设置正确的值" |
| D5 | 前提条件完整 | 权限、工具版本、环境要求均列出，执行者不会卡在"权限不足" |
| D6 | 联系人可联系 | 联系人有具体渠道（Slack handle / PagerDuty / 电话），不是"联系运维" |
| D7 | 无需理解原理 | 执行者按步骤做就能完成，不需要"理解系统架构后再操作" |
