# README（项目首页）
> 让第一次打开仓库的人在一屏内知道：这是什么、适合谁、怎么开始，以及去哪里找更多信息。

> **示例使用范围**：保留已核验的 ripgrep 开头定义与不适用场景、uv 安装节两段节译，只示范首段定义、适用边界和安装写法，不是目标项目事实。见[来源说明](../examples/SOURCES.md)。

## 文风

- 读者是第一次来的访问者，用"你"称呼；首段用陈述句说清是什么，安装和使用步骤用祈使句。
- 每个性能或体验声明都要有依据：基准链接、测量条件或可复现命令；没有依据就写事实，不写"极快""强大""开箱即用"。
- 不适用的场景写成具体条件，必要时指向替代工具（见 ripgrep 示例）。
- README 只放首次使用需要的内容；完整配置、API 和设计说明链接到 `docs/`，不在首页展开。
- 仓库内链接和图片用相对路径；有多语言版本时，在标题下方放语言切换链接。

## 变体选择

```
仓库交付的是什么？
  ├─ 命令行工具、库、插件或 Agent Skill   → 工具与库（默认）
  ├─ 需要部署或运行的应用、服务          → 应用与服务
  └─ 文档、规范、清单或资料合集          → 资料仓库
```

章节名按 Standard Readme 规范：背景（按需）/ 安装 / 用法 / 贡献 / 许可证，许可证放在最后一节。标题、短描述、标志、徽章和首段是规范元素，不设 `##` 章节。

## 变体 A: 工具与库

> 读者装好就用。首屏给一句话定义和最短可运行示例。

### 必需内容

| 必需内容 | 本节回答 | 排版 |
|--------|------|------|
| 标题与短描述 | 项目叫什么？一句话做什么？ | 不设 `##`：标题 + 一句话（120 字符以内，与包管理器描述一致） |
| 首段 | 默认行为是什么？支持哪些平台？和哪些工具类似或不同？ | 不设 `##`：短描述后一段，倒金字塔 |
| 安装 | 怎么装？ | 推荐方式在前，备选在后；每种方式一个代码块，写明适用平台或前提 |
| 用法 | 第一次怎么用？会看到什么？ | 最短可复制命令 + 预期结果 |
| 贡献 | 去哪里提问？接受 PR 吗？ | 一两句 + 链接到 CONTRIBUTING |
| 许可证 | 用什么许可证？ | 最后一节：SPDX 名称 + 指向 LICENSE 的相对链接；仓库没有许可证时省略本节，缺口写进交付说明 |

### 按需模块

| 模块名 | 本节回答 | 排版 | 格式规范 | 保留条件 |
|--------|------|------|----------|-----------|
| 背景 | 项目为什么存在、解决什么问题？ | 一到两段 | 现状、问题与约束；与首段不重复 | 首段放不下动机时使用 |
| 标志 | 项目有标志吗？ | 标题上方或下方一张图 | 相对路径图片 + 描述性 alt；尺寸写明 | 仓库里已有标志文件时使用；没有时不放占位图 |
| 徽章 | 构建、版本、许可证状态？ | 标题下一行 | 只放能反映真实状态的徽章，无标题 | 每个徽章指向真实来源；装饰性徽章删除 |
| 目录 | 内容较长时怎么快速定位？ | 链接列表 | 链接到各 `##` 章节 | README 超过 100 行时使用 |
| 演示 | 用起来是什么样子？ | 截图、GIF 或终端输出 | 一张图 + 一句图注，说明演示条件 | 图来自真实运行；性能图写明测试条件 |
| 特性 | 有哪些主要能力？ | 无序列表，按真实能力列，不设条数下限 | 每条一个能力 + 链接到详细文档 | 每条都能对应真实功能；空泛形容词删除 |
| 适用范围 | 哪些场景不适合？ | 无序列表 | 每条一个具体条件，可给替代工具 | 有具体条件则有效；"可能不适合所有人"无效 |
| 文档 | 详细文档在哪？ | 索引 + 深链 | 指南、参考、FAQ、变更日志各一个链接 | 链接目标存在 |
| 维护者 | 谁在维护？ | 无序列表 | 姓名或账号 + 链接 | 有明确维护者时使用 |
| 致谢 | 谁的工作被使用或参考？ | 无序列表 | 每条一个来源 + 链接 | 有真实依赖或参考来源时使用 |
| Star 趋势 | 项目关注度如何变化？ | 图 | 放在许可证之前；用下方片段，替换 `OWNER/REPO` | 仅公开 GitHub 仓库使用 |

## 类型验证标准

通过核对清单（`references/verify.md`）后，额外检查以下 README 专用项：

| # | 检查项 | 判定标准 |
|---|--------|---------|
| R1 | 首屏回答三件事 | 只读标题、短描述和第一段，能说出项目是什么、适合谁、怎么开始 |
| R2 | 命令可复制 | 安装和用法的命令完整，不含未说明的占位符；写明适用平台或前提 |
| R3 | 声明有依据 | 性能、兼容性和"支持"类声明有链接、测量条件或明确的未验证说明 |
| R4 | 链接有效 | 仓库内链接用相对路径且目标存在；外部链接指向一手来源 |
| R5 | 许可证在最后 | 有许可证时是最后一节，写明 SPDX 名称并链接 LICENSE；Star 趋势图在其前 |
| R6 | 不越界 | 完整配置、API 和设计细节已链接到独立文档，首页只保留首次使用需要的内容 |
| R7 | 多语言一致 | 有多个语言版本时，各版本的命令、链接和版本号一致，并互相链接 |
