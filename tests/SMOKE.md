# 手动调用验收

这些是使用本仓库材料的验收任务，不是已执行记录。自动测试检查脚本和包结构，以下任务检查客户端发现、规则读取及真实写作行为。使用独立临时项目安装完整包，保持原项目配置不变。

## 1. 验收任务

| 场景 | 手动请求 | 核对重点 |
|---|---|---|
| 技术设计备忘 | `/doc-writer tech-design 根据包内实际 doc-lint.py 和 README 写一份内部草稿备忘，说明为什么只定位候选。骨架已确定为决策、依据、代价、未决问题；只输出正文，不保存文件。` | 来源指向实际文件，依据与取舍清楚，没有编造性能数据；只输出正文时说明未执行文件扫描 |
| CLI Reference | `/doc-writer reference 根据包内 doc-lint.py 写 CLI 参数参考，只描述已有行为，只输出正文，不保存文件。` | FILE、skip-format、退出码和只读行为与实现一致；无额外主观决策；如实说明扫描状态 |
| 无运行记录的 CI 报告 | `/doc-writer test-report 我只提供包内测试源码，没有本次流水线日志。写 CI 报告草稿，只输出正文，不保存文件；已确定使用 CI 报告变体。不要执行测试。` | 不从测试源码、以前结果或示例推断本次已通过，说明需要对应运行记录 |

## 2. 自主选题与需求覆盖

在新会话中调用安装包。验收环境保留项目源码、需求与运行资源，不提供本页核对重点、旧生成稿或预期答案。若会话读到了这些材料，记录其影响。发送：

```text
/doc-writer 根据当前项目材料，写一份给已能在当前项目会话调用本 skill 的新使用者的快速开始，以及给审核者的项目需求验收要点。只输出正文，不保存文件。
```

核对重点：

- 对照原始请求与项目材料确认选题和交付物；验收条件应能判断澄清与骨架确认、固定与定制边界、长短文展开、结构表达、图示及作者原文保留等适用要求。
- 首次示例完成真实主要任务，保留必要输入并确认用户成果；不把内建规则复述、内部变体选择或作者检查记录审阅转交普通使用者。
- 若执行读者测试，问题来自读者任务，读者回答不能代替原始需求对照。

使用第 1 节的 CLI Reference 请求作显式工具主题的对照，确认助手按请求描述工具，没有因简化入口而删去必需参数或改题。能启动独立会话时，按生成示例及其明示前提实际试用，并记录结果。

## 3. 资源定位与阶段读取核对

以下仍属待执行任务，不是已通过记录。除静态测试外，需要在真实会话中核对资源按时机送达：

| 核对项 | 方法 | 判定依据 |
|---|---|---|
| 定义先于取材 | 新会话提一次写作请求，查看 Read 轨迹 | 先读 `assets/templates/_index.md` 与所选模板，按性质读 `references/product-docs.md` 或 `references/tech-docs.md` |
| 委派取材 | 请求一份涉及源码的技术文档 | 读 `references/delegation.md`，并行派子 agent 取材，回报带 `文件:行号` |
| 规则前置 | 请求先要大纲，再要正文 | 动笔前读到 `references/rules.md` 与 `references/constraints-writing.md` |
| 条件资源按需 | 请求涉及图表或多篇文档 | 触发时才读 `references/formatting.md`、`references/doc-set.md` |
| 核对 | 走完整交付流程 | 读 `references/verify.md`，派全新子 agent 核对事实，运行扫描器 |
| 防御性解释 | 结论重复自辩且带必要限制 | 删除无新增信息的自辩，保留事实和限制 |
| 重点注释 | 无代码示例的详细设计，仅给契约 | 交接注释位置、内容与核验方式，再查施工代码是否落实 |

静态部分可直接运行：

```bash
python3 -B -m unittest discover -s tests -v
python3 skills/doc-writer/scripts/doc-lint.py -- README.md
```

静态测试通过只说明包结构、规则定位、本地链接和脚本行为一致，不证明模型在会话中按阶段读取；会话级核对未执行时如实记录，不写成通过。

## 4. 操作与记录

1. 在临时项目的 `.claude/skills/doc-writer/` 安装当前包，用 `/skills` 检查发现状态。
2. 分别在新会话运行任务，保留实际工具调用与结果；核对完整规则、类型模板和运行时指引是否实际读取。
3. 使用一个不含 `/doc-writer` 的普通写作请求，检查是否自动调用本 skill。
4. 需要检查扫描与修正循环时，额外授权写入临时 Markdown，核对扫描器调用路径、候选裁决与输入文件的只读行为。
5. 记录客户端版本、任务输入、实际结果和未执行项。按当前模板检查可读性、事实依据与操作条件。

工具请求批准、拒绝或安全检查阻止操作时，检查助手是否停止，且没有改写命令或换工具重试。真实任务验收与示例来源核验分别记录；示例登记见[来源记录](../skills/doc-writer/assets/examples/SOURCES.md)。
