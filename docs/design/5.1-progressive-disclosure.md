### 5.1 渐进式披露

**问题**：写好一份文档需要的规则（结构、语言、技术重点、图表、文档集对齐、核对）远多于一次任务实际用到的。全部放进入口，模型读不完也记不住；拆得太碎，规则重复、权威不清。

**解决方案**：入口只写五步流程和资源表，规则按"什么时候用到"拆成几个独立文件，每条规则只在一个文件里写。模型按当前动作读取；字面候选交给脚本定位。

#### 5.1.1 加载

| 文件 | 内容 | 读取时机 |
|---|---|---|
| `SKILL.md` | 定义文档 → 取材 → 大纲 → 编写 → 核对与交付；资源表；边界 | 用户提出文档任务时 |
| `assets/templates/_index.md` 与选定模板 | 类型、变体、标准章节名、类型验证 | 第 1 步选类型；选定模板完整读 |
| `references/product-docs.md` | 产品语言、PRD 要讲清的内容、用户视角呈现 | 产品类文档 |
| `references/tech-docs.md` | 技术语言、技术重点清单、架构论证、测试口径、示例 | 技术类文档 |
| `references/delegation.md` | 子 agent 分档、取材清单、派发格式、事实核对 | 取材和核对前 |
| `references/rules.md`、`references/constraints-writing.md` | 结构、内容、真实性、密度；G1 禁用句式 | 动笔前 |
| `references/formatting.md` | 图、表、代码块、排版 | 用图表前 |
| `references/doc-set.md` | 篇数、权威归属、术语表、读者分层、修改后全文对齐 | 写或改多篇文档时 |
| `references/verify.md` | 事实核对、自检清单、候选扫描 | 初稿完成后 |

```
文档任务 → SKILL.md
  ├─ 第 1 步 定义：_index.md + 模板；按性质读 product-docs 或 tech-docs
  ├─ 第 2 步 取材：delegation.md → 并行派子 agent
  ├─ 第 3–4 步 大纲与编写：rules + constraints-writing；用图表时 formatting
  │     └─ 多篇文档：doc-set
  └─ 第 5 步 核对：verify.md → 子 agent 核对事实 → 自检 → doc-lint.py
```

**取舍**：v3 删除了 H1–H9 启发式、收尾检查合并映射和快速路径。它们复述规则或给规则加豁免，读的人要在多处对照；实验显示这些叠加的约束让输出变得防御、啰嗦（大量"未验证""不保证"）。现在每条规则只有一个出处，短文档由"篇幅跟内容走"自然变短，不需要单独的快速路径。

#### 5.1.2 脚本辅助

**设计取舍**：保留所有质量规则，只缩小脚本责任。字面扫描有助于定位，语义判断仍由模型承担；不为达到固定数量增加算法。

##### 各类检查的执行方式

| 检查 | 对应规则 | 首版执行方式 |
|------|---------|-------------|
| 禁用句式扫描 | G1 句式清单 | 模型完整检查；脚本仅定位纯字面片段，不自动编译占位符或跨句模板 |
| 禁用修饰词扫描 | G1 修饰词 | 脚本定位词项；模型判断有无度量 |
| 禁用大词扫描 | G1 大词 | 脚本定位词项；模型判断定义、具体变化和必要性论证 |
| 术语一致性 | rules.md §2 一物一名 | 模型判断同一概念的命名和含义，不做词频聚类 |
| 凑数章节 | rules.md §4 密度 | 模型判断内容是否为凑形式而填充，不用字数方差判违 |
| 结构化表达 | formatting.md | 模型按阅读单元检查真实结构与必要短段，纠正连续多段纯散文及逐段套列表、表格 |
| 标题空泛检测 | rules.md §1、verify.md 自检 | 模型对照标题与正文判断，不用标题大词命中判违 |
| 格式一致性 | 排版规范 | 脚本提示标点、间距、括号候选，模型结合文档规范裁决 |

##### 执行方式

```
核对：子 agent 事实核对 + 主 agent 自检
    ↓
[工作流直接调用] scripts/doc-lint.py 扫描当前稿
    ↓
输出：文件:行号:类别:命中文本
    ↓
模型逐项修正、按上下文保留或标为需确认
```

**误报处理**：全部输出均为候选，不把字面命中当作已确认违规。脚本不改写输入。退出 `0` 表示扫描完成，退出 `2` 表示执行故障；无候选不代表质量通过。

##### 脚本设计原则

- 单个 Python 3 标准库脚本，无第三方依赖、无配置框架、无自动安装。
- 直接从 `references/constraints-writing.md` 的 G1 表和词项列表读取候选词源，以 G1/G3 标题为边界，不另维护硬编码词表或新规则 ID；必要结构解析失败必须报错，不回退旧主规格。
- 有限排除围栏代码、行内代码、URL 和开头元数据，保留原始行号。块引用及链接可见文本不全部豁免。
- `<!-- doc-lint: ignore-next-line 原因 -->` 仅影响下一物理行的脚本候选，并报告应用情况；不豁免模型检查。
- 中文格式默认警告；`--skip-format` 可重复选择 `punctuation`、`spacing`、`parentheses`。Python、脚本或权限不可用时由模型完整检查并说明未执行原因。

#### 5.1.3 文件组织

技能包在 `skills/doc-writer/`，按 Agent Skills 规范分目录；仓库根目录只放 README、测试、eval 和维护文档，不随技能安装。

```
skills/doc-writer/
├── SKILL.md                 # 入口：五步流程、资源表、边界
├── LICENSE
├── scripts/doc-lint.py      # 只读候选扫描器
├── references/
│   ├── rules.md / constraints-writing.md     # 通用规则；后者是扫描器词源
│   ├── product-docs.md / tech-docs.md        # 按文档性质
│   ├── delegation.md / doc-set.md            # 委派、多篇文档
│   └── formatting.md / verify.md             # 图表、核对
└── assets/
    ├── templates/           # _index.md、12 类模板、tech-design/ 分支
    └── examples/            # 已核验示例、SOURCES.md、licenses/
```

本文件、`design-spec.md`、`5.2-document-templates.md` 和 `5.8-structured-expression.md` 是维护文档，放在仓库 `docs/design/`，运行时不读。

**跳转模型**

| 层 | 文件 | 谁指向它 | 它可以链接到 |
|---|---|---|---|
| 0 | `SKILL.md` | 无 | 第 1 层（资源表列出） |
| 1 | `references/*.md`、`_index.md` | 只有 `SKILL.md` | 第 2 层 |
| 2 | 类型模板 | `_index.md` | 分支模板、示例、`SOURCES.md` |
| 3 | `tech-design/` 分支模板 | 技术设计模板 | 示例 |
| 叶 | 示例、`SOURCES.md`、许可证副本 | 模板 | 无 |

规则：

- 链接只向下。指向第 0、1 层或同级文件时只写代码格式路径（如 `references/tech-docs.md`），表示出处，不做链接。
- 第 1 层之间不互相链接，阅读顺序只由 `SKILL.md` 决定。
- 全图最长四跳（入口 → 类型索引 → 技术设计模板 → 分支模板 → 示例）。
- `tests/test_package_contract.py` 检查：入口资源表覆盖全部 `references/` 文件；无环、最长链不超过 4 跳、非入口文件不链接第 0/1 层。

#### 5.1.4 设计文档自身的披露

- `docs/design/design-spec.md`：设计背景与模块摘要；只供维护者阅读
- `skills/doc-writer/references/`：运行时规则的唯一原文
