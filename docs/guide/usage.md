# 使用指南

## 写一篇新文档

在请求里写清读者、用途和可用材料。需要保存时写明路径，没有路径时助手只输出正文。

```text
用 doc-writer 根据 src/ 和 README.md，为新加入的工程师写一份快速开始，保存到 docs/quickstart.md。
```

简单请求默认写一篇文档。只有你要求，或两类读者的任务一篇完成不了时才拆成多篇。

## 助手会做什么

1. 定义：写清文档做什么、给谁看、回答哪些问题、范围多大。前提也在这一步定。
2. 研究：并发派子 agent 读代码和资料，笔记每条附 `文件:行号`，发现的边界和风险另记一份。
3. 解决：逐条查清、删除，需要你决定的不阻塞写作，交付时一次问你；你确认要写的再补，答不需要的就丢掉。
4. 梳理：写章节大纲和术语表。
5. 写作：新上下文的写作 agent 按片段类型读对应的写作指南，只写结论。
6. 核查：三个不继承写作上下文的核查 agent 并行检查事实与一致、需求与范围、文风与排版，各写一张证据表；助手按证据表统一修改，再运行 doc-lint。

环境不能派子 agent 时，主 agent 按同样的阶段自己做，核查按三张表依次自查，并在交付说明里写明没有独立核查。

## 修改与审查

- 修改已有文档：给出路径和要改什么，助手会在改完后做核查，查旧名残留和多篇之间的矛盾。
- 只审查：说明「列出位置和建议，不修改文件」，助手只派核查 agent 写证据表，不改文件。

```text
用 doc-writer 检查 docs/architecture.md 的结构、术语和实现描述，列出具体位置及修改建议，不修改文件。
```

## 单独运行 doc-lint

```bash
python3 skills/doc-writer/scripts/doc-lint.py docs/quickstart.md
python3 skills/doc-writer/scripts/doc-lint.py --skip-format spacing docs/quickstart.md
```

扫描结果只是候选：命中不等于违规，零命中也不等于合格。需要 Python 3.9 或更高版本，只用标准库；脚本不修改输入文件。

## 授权

保存或覆盖文件需要你授权。文档里描述的部署、迁移、删除操作只写不做。数据、运行结果和截图只写真实取得的，拿不到时助手会写明缺什么。
